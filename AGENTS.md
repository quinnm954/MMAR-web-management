
- Fleet prospecting: edge function `prospecting` (search/enrich, admin-only) + hourly `prospect-email-worker` sending trade-specific plain-text copy from `_shared/prospect-copy.ts` (mirrored in `src/lib/prospectCopy.ts`) via a separate sales sender (Resend, `RESEND_API_KEY`) on its own subdomain, never the app email sender; why: cold outreach must not hurt customer email delivery. No automated calls/texts (TCPA).

- Fleet registration: /fleet/register signs up via auth then calls anon-executable `submit_fleet_registration` RPC, guarded by user id+email match within 15 min of account creation.
- App emails are sent only from edge functions via `_shared/send-and-log.ts` (managed send + email_send_log row); why: the admin Emails screen reads that log and the browser must never send directly.
- Staff calendar feed: public `calendar-feed` edge function serves ICS keyed by a per-user token in `calendar_feed_tokens` (issued/rotated via `get_calendar_feed_token` RPC); technician-only users get just their assigned appointments; why: phone/PC calendar widgets need an unauthenticated subscribable URL.
- Customer follow-ups (estimate nudges, invoice auto-send/reminders, review requests) run in the hourly `followup-worker` edge function with per-row counters on estimates/invoices; why: one bounded, idempotent job instead of many crons, and texts stay gated by `smsAllowed()` until A2P is approved.
- The Admin Phone workspace is the only admin screen for calls, texts, in-app chat and email (separate Calls/Texts/Emails tabs and the admin Messages page redirect to it); customers and techs keep /messages; why: the owner wants all communication in one place.
- Repair-order names derive from approved estimate repair lines, preferring labor descriptions; why: orders must identify the repair rather than the estimate workflow state.
- Technician agreement: `technician_agreements` table (admin-only RLS) signed by techs via token link through `get_technician_agreement`/`sign_technician_agreement` RPCs; text lives in `src/lib/techAgreement.ts`; why: techs sign on phone without an account.
- Website booking requests get an unsent draft estimate at submission (notify-booking-request → booking_requests.draft_estimate_id), which estimate-for-appointment reuses on confirmation; why: the shop sees a price before booking, without auto-sending or duplicating estimates.
- Inbound customer email is pulled from the linked Outlook inbox by the 5-minute `outlook-inbox-sync` function into `inbound_messages` (deduped by Graph id); why: Outlook push isn't available via the connector and the Phone page reads that table.
- The admin Phone also runs as its own home-screen app at /admin/phone (separate phone.webmanifest swapped in at runtime, fullscreen AdminPhoneHub with left-edge swipe back); why: Mike uses it on his iPhone like a native phone app.
- Web push subscriptions carry an `app` tag ('main' | 'phone'); send-web-push routes `message_updates` to phone-app subscriptions when present (else main) and all other categories to main; why: communication alerts belong in MMAR Phone, service alerts in Garage Ace.
