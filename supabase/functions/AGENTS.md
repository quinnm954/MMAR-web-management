- Fleet prospecting: edge function `prospecting` (search/enrich, admin-only) + hourly `prospect-email-worker` sending trade-specific plain-text copy from `_shared/prospect-copy.ts` (mirrored in `src/lib/prospectCopy.ts`) via a separate sales sender (Resend, `RESEND_API_KEY`) on its own subdomain, never the app email sender; why: cold outreach must not hurt customer email delivery. No automated calls/texts (TCPA).
- Inbound customer email is pulled from the linked Outlook inbox by the every-minute `outlook-inbox-sync` function into `inbound_messages` (deduped by Graph id); why: Outlook push isn't available via the connector and the Phone page reads that table.
- Adding a texter as a customer uses the admin-only `extract-thread-contact` edge function (Lovable AI reads the SMS thread) to prefill a form, then saves via `admin-create-customer` and links `sms_threads.customer_id`; why: the AI only suggests and staff confirm before anything is saved.
- Estimate expiry runs in `followup-worker` (pre-expiry nudge at followup_count 2→3, then status `expired` after `valid_until`), and a trigger on `estimate_decision_logs` blocks customer approval of expired estimates; why: prices go stale and no extra schedule is needed.
- PartsTech punchout authentication uses `partstech-gateway/auth.ts` to require user access with distinct shop and software-partner credentials; why: shop credentials must never be substituted for the integration partner identity.
- App emails are sent only from edge functions via `_shared/send-and-log.ts` (managed send + email_send_log row); why: the admin Emails screen reads that log and the browser must never send directly.
- Staff calendar feed: public `calendar-feed` edge function serves ICS keyed by a per-user token in `calendar_feed_tokens` (issued/rotated via `get_calendar_feed_token` RPC); technician-only users get just their assigned appointments; why: phone/PC calendar widgets need an unauthenticated subscribable URL.
- Customer follow-ups, including day-before financing withdrawal SMS, run in the existing hourly `followup-worker` during 9am–7pm Eastern; financing uses Stripe's next billing/retry timestamp and per-installment reminder timestamps; why: no extra cron, invented charge time, or repeated successful reminders, and texts stay gated by `smsAllowed()`.
